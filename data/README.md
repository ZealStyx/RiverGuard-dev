# RiverGuard — NCR Daily Dataset v1

Generated by `data/generate_dataset.py` (Python 3, seed 42, deterministic).
Covers **2016-01-01 → 2020-12-31**, four NCR cities: Quezon City, Marikina, Manila, Pasig.

> **Read this before reporting any model metric.** The dataset is *partly real,
> partly modelled*. Section "Reliability" below states exactly which column is which.
> It is intended to unblock Phase 1/2 engineering (schema, features, pipeline,
> baselines). It is **not** a substitute for gauge observations and must not be used
> for operational flood warnings.

## Reliability — what is real and what is modelled

| Column | Status | Method |
|---|---|---|
| `Rainfall_mm` | **Synthetic, calibrated** | Markov wet/dry state + Gamma intensity, monthly totals rescaled to PAGASA 1991–2020 normals × U(0.85, 1.15); 60% shared NCR regional factor |
| `Rainfall_mm` for Manila, 2020-11-11/12 | **Real (ERA5)** | Open-Meteo ERA5 reanalysis: 44.3 mm and 178.4 mm |
| `Tmax_C`, `Tmin_C`, `ET0_mm` | **Synthetic, calibrated** | Monthly means from Port Area normals + noise; ET0 from temperature proxy |
| `SoilMoisture_pct` | **Derived** | Bucket: `SM_t = clip(SM_{t-1} + Rain - ET0 - 0.08·SM_{t-1}, 5, 95)` |
| `AntecedentRain_3/7/30d_mm` | **Derived** | Rolling sums shifted 1 day (no target leakage) |
| `WaterLevel_m` | **Derived, not gauge data** | `WL = base + 0.006·Ant7 + 0.018·Rain + 0.004·Ant3 + N(0, 0.10)`, calibrated so dry-season levels sit near base and extremes reach alarm bands |
| `FloodOccurrence` | **Rule-based proxy** | `WL ≥ Alarm1 OR (Rain ≥ 100 & Ant7 ≥ 150) OR Ant3 ≥ 250` → 1.8% prevalence (matches the supplied CSV's 1.8%) |
| `RiskLevel` | **Derived** | From WL vs. alarm bands + same-day rainfall |

**Calibration checks (see `Quality_Checks` tab):** 7,308 rows, no gaps, no duplicates,
no missing values, monthly rainfall within ±15% of PAGASA normals, Marikina WL range
11.2–15.9 m against alarm levels 15/16/18 m, flood prevalence 1.8%.

**Known limitations**

- City-level resolution only; no barangay/station-level cross-correlation, no tidal
  backwater for Pasig/Napindan, no dam operation (Wawa, Angat, Ipo, La Mesa).
- Water level is a rainfall-driven proxy — it cannot reproduce surge timing or
  backwater effects, so lead-time studies on this data are only indicative.
- Synthetic storm events (2018-08-06, 2019-09-14) are deliberate calibration
  stress-tests, flagged in `Notes`; they are not observations.
- Pasig alarm thresholds (12.0 / 12.5 / 13.0 m) come from a secondary source and
  are marked "verify" in the `Thresholds` tab.

## Units, timezone, licensing

- **Units:** rainfall mm/day, water level m (gauge datum per river; not a common
  vertical datum), soil moisture %, temperature °C, ET0 mm/day.
- **Timezone:** all dates are Asia/Manila (UTC+8) local calendar days. No `timestamp`
  column in the CSV — the Convex `sensorReadings.observedAt` field should be set to
  00:00 Asia/Manila for each row.
- **Licensing:** no third-party raw data is redistributed. PAGASA normals/thresholds
  are cited facts; ERA5 values are re-derived from the Open-Meteo API (Copernicus
  ERA5, CC-BY-4.0). The synthetic table itself is generated by this repository.

## Upgrade path to operational grade (Phase 1 exit criteria)

1. Replace `Rainfall_mm` with PAGASA AWS / EFCOS gauge series per station.
2. Replace `WaterLevel_m` with PAGASA FFWS / EFCOS telemetry at Sto. Niño (Marikina),
   Rosario and Pandacan (Pasig).
3. Replace `FloodOccurrence` with LGU-validated event records (Marikina MDRRMO,
   Pasig DRRMO, QC DRRMO) plus validated news/NDRRMC reports.
4. Keep this file's column names and sheet layout so the ingest path in
   `convex/schema.ts` (`stations`, `sensorReadings`) needs no change.
